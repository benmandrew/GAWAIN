# RERS 2016/2017: the mistranslated pattern properties

The RERS 2016 and 2017 sequential LTL tracks contain 105 properties whose formula does not say what their English gloss says. Each one has the shape `false R (Q & ψ)`, that is G(Q ∧ ψ), where the gloss describes a scoped Dwyer pattern G(Q → ψ). The conjunction needs Q at every position, so every one of these properties is false on its model. This note records how the 105 cases were checked and how they became the benchmark set `bench/sets/rers-precedes.csv`, in which the intended pattern is the weakening of the shipped formula.

## Counts and patterns

The script `bench/rers_precedes.py` finds the cases with the regular expression `^\(false R \(([io][A-Z]) & (.*)\)\)$`. It finds 40 cases in 2016 (6, 6, 7, 5, 5, 3, 1, 5 and 2 over problems 1 to 9) and 65 in 2017 (7, 5, 8, 6, 9, 9, 5, 9 and 7). This confirms the counts of 40 and 65. The parallel track has no affected property: its 700 properties carry no gloss and none has the `G(atom & …)` shape.

The name "precedes" covers only half of the set. The glosses match three patterns from Dwyer, Avrunin and Corbett, "Patterns in Property Specifications for Finite-State Verification" (ICSE 1999, catalogue at <https://matthewbdwyer.github.io/psp/>). There are 54 cases of *precedence after Q until R*, `G((Q & !R) -> (!S W (P | R)))`. There are 35 cases of *response after Q until R*, `G((Q & !R) -> ((P -> (!R U (S & !R))) W R))`. The remaining 16 are the *two-cause response chain*, `G((P & X F T) -> X F(T & F S))`. The fix replaces `(Q &` with `(! Q |`. Spot 2.15.1 shows for all 105 cases that the fix is equivalent to the pattern built from the gloss, that φ implies the fix and that the fix does not imply φ. The last result holds in plain LTL and also under the RERS trace assumption that exactly one atom holds at each position.

## Semantics

RERS reads a property over the infinite runs of the program, and an invalid input ends the run. On 2016 problem 1 this reading reproduces all 100 official verdicts. The other reading, in which the program ignores an invalid input and continues, gives 14 mismatches. All the routes below use the first reading.

## Routes to a verdict

No verdict in the set is a guess. Each comes from one or more of six sound routes, and the build stops if two routes disagree. A route that claims a formula holds is trusted on a problem only when it matches the official verdicts there: it must prove no officially false property, and the note gives how many officially true ones it proves. A route that claims a formula fails must give a lasso that replays on the compiled program and that Spot accepts as a run violating the formula.

**Explicit search.** `bench/rers_seq.py` compiles the C program with an input harness and explores its state space breadth-first, with the `.data` section as the state. It then builds a *known-runs automaton*: the explored graph plus every official counterexample lasso that replays as a real run. A formula fails when Spot finds a run of this automaton that violates it. It holds only when the exploration was complete. Only 2016/1 (51 states), 2017/1 (493) and 2017/2 (315) are complete. On those three problems the route matches all 100 official verdicts on each. The other 15 problems stop at the 300,000-state cap. Of the official lassos, between 44 of 74 (2017/5) and all of them replay as real runs, 1,030 of 1,179 in total. A lasso that does not replay within 3000 loop rounds is left out, and it costs only completeness. On av3, with about 10 other processes running, a problem took between 35 s and 936 s.

**Implication from the official verdicts.** If an officially true property ψ satisfies ψ ∧ one-event → fix, the fix holds. If ψ ∧ one-event → ¬fix, no run satisfies the fix.

**nuXmv.** `bench/rers_seq_smv.py` translates the C program into an SMV model and checks it with nuXmv 2.1.0 IC3 (`check_ltlspec_ic3`). The programs are tables of event-condition-action rules, and the translator refuses any file outside that shape. Globals that take part in arithmetic become `signed word[32]`, whose division, `mod` and overflow match C compiled with `-fwrapv` (checked with `-7 / 2`, `-7 mod 2`, `7 / -2`, `7 mod -2` and `2000000000 * 3`). Constant arrays and pointers to them become case expressions. A separate invariant `G !oob` must hold, which shows that no executed array read is out of bounds. A problem's nuXmv verdicts are used only when that invariant holds and every decided shipped property matches its official verdict. On 2016/1 and 2017/1, nuXmv matches all 100 official verdicts on each and agrees with the explicit route on every fix. On 2017/2 it decides only 7 checks within the time limit, and all 7 agree. On 2017/4, IC3 decided 14 of 25 checks within 3 hours per session, all in agreement.

**Interval abstraction.** `bench/rers_seq_abs.py` replaces each global that takes part in arithmetic by the interval cell it lies in, where the cells come from the constants the program compares that global with. Each abstract state also carries a box, the hull of the concrete values reached so far, and a rule fires only when its guard can be true inside the box. The search over abstract states is an over-approximation, so when it completes, a formula that holds on the abstract automaton holds on the program. A formula that fails on the abstract automaton gives an abstract lasso (`autfilt --product`, then `--stats=%w`), and that lasso counts only when it replays on the compiled program within 60, 600 or 3000 loop rounds and Spot accepts it. The abstraction is cross-checked against the compiled program: every explored program state must map to an abstract state whose box holds its values, and every concrete edge must be an abstract edge (`rers_seq_abs.py crosscheck`). On 2016/2, 2016/3, 2017/2 and 2017/3 this check covers between 573 and 208,335 concrete edges, and none falls outside the abstraction. The search completes on 7 problems: 2016/1, 2, 3 and 5, and 2017/1, 2 and 3 (26 to 48,542 abstract states, at most 90 s each on a 20-core workstation at a load of about 5). On those 7 it proves 281 of the 281 officially true properties and none of the officially false ones. On the other problems it does not converge. It was stopped at 6.19 million abstract states on 2017/5, 8.96 million on 2017/6 and 2.09 million on 2017/9, and it ran out of memory at 21.0 million on 2017/4 (all on av2).

**Output alphabet.** Every output in these programs is a `printf("%d\n", K)` with a literal K, and `bench/rers_precedes.py` asserts that no other kind of `printf` to standard output exists. An output whose value appears in no such call is false at every position of every run. With those outputs set false, Spot checks whether `one-event ∧ GF(input) ∧ GF(output) ∧ G ¬absent ∧ ¬ψ` is unsatisfiable, which proves ψ on the model. Over all 18 problems this route proves 296 shipped properties, all officially true, and no officially false one. For example 2017/5 never prints R or Z, and 2017/4 never prints Z.

**Random walks.** `bench/rers_seq_walk.c` drives the compiled program with random inputs and runs a monitor for the pattern of the fix beside it. When the monitor reaches a point where the fix is violated (or, for the response patterns, an obligation is open), a breadth-first search over program states from that point looks for an edge back to a state on the current path, which closes a lasso. `bench/rers_seq_walk.py` replays the lasso to recover the outputs and accepts it only when Spot finds the lasso automaton and the negated fix intersect. With 2000 walks of 2000 steps and a 20,000-state cycle search, the walks find a counterexample for all 78 fixes that fail, in 654 s in total (median 0.1 s, maximum 173 s, on the 20-core workstation at a load of about 5). On the 27 other fixes, 20,000 walks of 2000 steps each find no violation (708 s in total). The walks are only a source of counterexamples: a walk that finds nothing proves nothing.

## Results

All 105 shipped formulas are *degenerate*: M ⊨ ¬φ. Spot proves this for every model at once, because φ ∧ one-event ∧ GF(input) ∧ GF(output) is unsatisfiable, and every run of a RERS program alternates single inputs and outputs forever. The model checkers also confirm it directly on 47 cases: the explicit route on 18, nuXmv on 17 and the abstraction on 44.

The intended weakenings split into 78 that fail, 23 that hold and 4 that are undecided. Every failing case has a real counterexample run from both the explicit route and the walks, and nuXmv confirms 8 of them. By pattern, precedence gives 37 fail, 15 hold and 2 unknown, response gives 27, 8 and 0, and the response chain gives 14, 0 and 2. No two routes disagreed on any value, and no verdict disagrees with an official one. In 2 of the failing cases (2016/1 property 86 and 2017/1 property 5), no run of M satisfies the fix, so the weakening is itself degenerate. The CSV records the route of each verdict in the `*_route` columns.

Of the 23 that hold, 10 come from the three problems on which explicit search completes, and nuXmv also proves 8 of these 10. The abstraction proves 2016/3 properties 43, 56 and 88 and 2017/3 property 22, which were undecided before. The output alphabet proves 2017/5 properties 47, 61, 80 and 83. Properties 47 and 83 open their scope at output R, and properties 61 and 80 say that output Z needs a cause first. 2017/5 never prints R or Z, so the scope never opens in the first two and the forbidden event never occurs in the other two. The alphabet also proves 2016/3 property 56, 2017/3 property 22, 2016/8 property 58, 2017/6 property 62 and 2017/7 property 39 a second time. The last 3 of those also follow by implication from an officially true property, as does 2016/6 property 85.

2017/4 property 60 rested on nuXmv alone (6318 s), on a model checked against only 6 official verdicts. It now has a second, independent proof. The fix says that output O precedes output Z after output U until output W, and 2017/4 never prints Z, so the alphabet route proves the fix. That route proves no officially false property on 2017/4 or on any other problem.

The 4 undecided cases are 2017/5 properties 26 and 87 (both response chains with trigger input N), 2017/6 property 92 (precedence after output W) and 2017/9 property 88 (precedence after input O). Each depends on one event: input N for the two 2017/5 chains, and output W for 2017/6 property 92 and 2017/9 property 88. If those events are unreachable, all 4 fixes hold, but no route proves it.
 The walks never see input N on 2017/5 or output W on 2017/6 in 40 million steps each (20,000 walks of 2000 steps), so the pattern's trigger never fires. On 2017/9, input O occurs and arms the monitor in 4.2 million of 40 million steps, but no step violates the fix, and a separate run of 4 million steps never sees output W. Longer walks of 20,000 steps on av2 (32 cores, load about 30) give the same outcome. On 2017/6, 4 seeds of 100,000 walks (8 billion steps, about 2300 s per seed) never see output W. On 2017/9, 6 seeds of 15,000 walks (1.8 billion steps, 1356 s to 2743 s per seed) arm the monitor in 320 million steps and never violate the fix. On 2017/5, 4 seeds of 1 million walks per property (20 billion steps per seed and property, 3477 s to 5131 s each) never see input N.

Every other route stops on these problems. The abstraction does not converge (above). Explicit search to 3,000,000 states finds no counterexample on 2017/5 and runs out of a 12 GB cap on 2017/6 and 2017/9. `bench/rers_seq_invar.sh` asks nuXmv for the invariant that the event never occurs (`check_invar_ic3` on `ev != e_iN` or `ev != e_oW`), and with it the bounds invariant `!oob` on 2017/6 and 2017/9. On 2017/5, SMT-based IC3 (`go_msat`) runs out of memory at 40 GB, and the bit-level build (`go_bmc`) at 16 GB. On 2017/9 both builds stop with a segmentation fault. On 2017/6 the bit-level build also runs out of memory at 16 GB, and SMT-based IC3 had not finished the bounds invariant when it was stopped after 2.5 hours. An undecided weakening has no known counterexample, but the set marks it unknown and does not count it as true.

## Reproducing

The script `bench/rers_seq.py fetch` downloads the four archives (URLs in the script) into `bench/data/rers/`. Then `sh bench/rers_seq_run.sh check 4 12 3600 OUT --only-affected --max-states 300000` runs the explicit route, `bench/rers_seq_smv.py check --out-dir OUT2` runs nuXmv, `bench/rers_seq_abs.py check --out-dir OUT3` runs the abstraction, `sh bench/rers_seq_walk_run.sh 1 8 14000 OUT4 2000 2000 20000 1 -- YEAR/PROB/PROP...` runs the walks, and `bench/rers_precedes.py OUT OUT2 OUT3 OUT4` writes the CSV. The alphabet route needs no separate run. The event invariants for the 4 undecided cases come from, for example, `sh bench/rers_seq_invar.sh 2017 5 40 21600 OUT5 msat go_msat iN`. The per-problem tables used for the committed CSV are in `bench/results/rers-precedes/`.

The set is small, but each row has an intended weakening that a person wrote, and most rows have a decided verdict. That makes it a direct check that a search for weakenings can recover what the property author meant.
